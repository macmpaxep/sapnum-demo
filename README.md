# SAPNUM — лендинг с формой заявок

Next.js 14 (App Router) + Tailwind + Supabase. SEO настроен из коробки:
`generateMetadata`, Open Graph, JSON-LD (Organization), `sitemap.ts`, `robots.ts`.

## Что нужно сделать, чтобы задеплоить сегодня (~30–40 минут)

### 1. Supabase (5 минут)
1. Зайдите на supabase.com → New project.
2. В SQL Editor выполните:
   ```sql
   create table waitlist (
     id uuid primary key default gen_random_uuid(),
     email text not null,
     company text not null,
     industry text,
     created_at timestamptz not null default now(),
     unique(email)
   );
   ```
3. Project Settings → API → скопируйте `Project URL` и `service_role` key
   (не anon key — форма пишет через серверный route, не напрямую с клиента).

### 2. Локально (10 минут)
```bash
npm install
cp .env.example .env.local
# вставьте в .env.local значения из Supabase
npm run dev
```
Откройте http://localhost:3000 и проверьте, что форма отправляется
(запись должна появиться в таблице `waitlist` в Supabase).

### 3. Деплой на Vercel (10 минут)
1. Залейте проект в GitHub-репозиторий (или используйте `vercel` CLI без git:
   `npx vercel` из корня проекта).
2. На vercel.com → New Project → импортируйте репозиторий.
3. В Environment Variables добавьте те же три переменные, что в `.env.local`:
   `NEXT_PUBLIC_SITE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`.
4. Deploy. Vercel выдаст домен вида `sapnum.vercel.app` — этого достаточно,
   чтобы звонить компаниям завтра. Свой домен можно подключить позже в
   Project Settings → Domains, без пересборки проекта.

### 4. Проверка перед звонками
- Откройте сайт с телефона — форма и вёрстка должны быть удобны на мобильном.
- Отправьте тестовую заявку и убедитесь, что она попала в Supabase.
- Замените `/public/og.png` на реальную картинку 1200×630 для превью в
  мессенджерах (сейчас файла нет — просто добавьте PNG с таким именем).

## Демо приложения (для показа предпринимателям)

По адресу `/demo/feed` (и `/demo/dashboard`, `/demo/catalog`, `/demo/metrics`)
лежит кликабельный прототип интерфейса — лента, дашборд, каталог товаров/услуг
и показатели, с ИИ-ассистентом и чатом в правой колонке на каждом экране.
Данные в нём статичные (моки из `lib/demo-data.ts`), это витрина, а не рабочий
бэкенд — ничего никуда не сохраняется. Меняйте тексты и цифры прямо в этом
файле под конкретного клиента перед звонком, если нужно.

## Дальше (после лендинга)
Это только входная точка воронки. Следующие приоритеты для самой платформы,
в порядке разумной очерёдности:
1. Авторизация + профиль компании (публичная SEO-страница `/company/[slug]`).
2. Дашборд метрик с ручным вводом (синхронизация с внешними сервисами —
   отдельная интеграционная работа, не первый шаг).
3. Лента постов/инсайтов.
4. ИИ-ассистент (чат поверх Anthropic API, с доступом к цифрам конкретной
   компании через system prompt/tool use).
5. Личные сообщения и групповые обсуждения (Supabase Realtime).

Каждый из этих пунктов — это отдельная неделя-две работы, не день.
